In plain language: double-clicking a chart opens a song page — one window for the whole song, showing its banner, background and jacket, its title, artist and pack, its music file with length and preview window, and all of its charts with meter, BPM and scores. From there you can play the song's preview and open the song's folder on disk. The page starts dependency-free for images (Tk reads PNG natively). The two real decisions are audio — an in-app preview needs pygame-ce, while the no-dependency alternative opens the file in your default player and plays the whole song instead of the preview window — and how the song folders are found, since the cache records only a virtual path and the folders live wherever the game was told to look (see §2). Everything else in this proposal is staging those choices so they can be made late.

## 1. Background and Goal

This is the feature Ian chose as the next target once the ground settled: Proposal 0010 is complete, v1.3.0 is released, and the docs pass (#184) is merged. His sketch (2026-11-15) is the spec in outline — a new window opened from a given chart, maybe via double-click, showing the song's associated data from the cache file, with all charts for that song pointing to an identical song page, and the preview playable from there. "Done" means a double-click on any chart opens that song's page, the page shows the media the cache already records, the preview plays the game's sample window, and the folder button opens the song's folder — with the page degrading gracefully when a pack has been rotated out and the folder is gone, since the cache keeps records of songs no longer on disk.

This change creates a new component boundary (`song_page.py`, following the 0009 dialog pattern), adds a constructor contract for it, and has two or more defensible designs where the choice constrains later work (image and audio dependencies, how the media reaches the page). It therefore needs a proposal under the workflow rule. It persists no new settings key in v1 (the roots are derived on every page open, §4) and bumps the snapshot schema 4 → 5 in stage 1 so existing libraries rebuild with media (§2).

## 3. The Decision: a new song-page component, media carried in the row, dependencies decided late

The recommendation is a new `song_page.py` component following the 0009 dialog pattern (geometry in, callbacks out), opened by double-clicking a chart row (or pressing Enter on it) through a new optional `on_open_row` callable input to `LibraryTable` — the table's tenth input — on the `show_rows` precedent. The song's identity is its `"Course path"`: the app hands the page every row sharing that value, so all charts for the song open the identical page. The media fields are carried as hidden row keys at parse time, on the "Score description" precedent — they are already in hand when the row is built, they survive the snapshot verbatim, and the page then works from snapshot-restored rows with no file re-read.

Folder resolution is a small Tk-free pair in a new module `library_media.py`: `song_roots(cache_dir)` returns the ordered root list, derived from `Preferences.ini` and the cache dir every time the page opens (one small file read, about 0.6 ms measured) — the `AdditionalSongFoldersWritable` entries (comma-split, reverse order within the list, since later mounts win), then the `AdditionalSongFoldersReadOnly` entries, then the `AdditionalFoldersWritable` entries (each plus `/Songs`), then the `AdditionalFoldersReadOnly` entries (each plus `/Songs`), then the user-data `Songs` — with the deprecated rule applied to both pairs (deprecated-if-nonempty, else Writable) — and `resolve_media_file(song_dir, filename, roots, kind)` probes each root in that order and returns the first file that exists, or `None`. Nothing is persisted: the install `Songs` root cannot be derived from the cache dir, so in v1 it is simply not supplied, and a library under the install folder resolves to "not found" (Q7). Resolution is per file, not per folder, because the engine's priority is per file — a split pack can take its banner from one root and its music from another, and the page must show the same files the game would. The resolver normalizes slashes, collapses `..` lexically, refuses any result outside the song's pack folder, treats absolute, drive-letter and VFS-top-relative values as "not found", and accepts only the engine's extensions for the given kind — images `.png`/`.jpg`/`.jpeg`/`.gif`/`.bmp` [CODE: `RageSurface_Load.cpp:23–30`], audio `.ogg`/`.oga`/`.mp3`/`.wav` [CODE: `RageSoundReader_FileReader.cpp:22–31`; `ActorUtil.cpp:536–540`] — so a path built from simfile text cannot open an arbitrary file through the external-player fallback. Media inside Packages ZIP/SMZIP archives is out of scope for v1: the resolver probes filesystem roots only, so a song whose media lives only in a zip shows placeholders, with the folder and play buttons disabled. Where no root holds the file, the page shows the media it has and disables the folder and play buttons for what it does not. A song under no root — an install-folder library, or a pack rotated out — shows 'not in the known song folders', not 'folder gone': the page cannot tell those two apart, and the wording must not claim a folder vanished when the truth is the viewer does not know that folder.

Images start dependency-free: `PhotoImage` for PNG, a placeholder for anything else, with Pillow as a named later enhancement for JPEG backgrounds and smooth scaling — not a v1 dependency. Stage 1 reports the BANNER/BACKGROUND/JACKET extension counts across the owner's real cache, so the Pillow call is made with data: if JPEG is rare it stays a later enhancement, if it is common it moves up. Audio is staged last, and the recommendation there is pygame-ce — not pygame, which has no Python 3.14 Windows wheel — for the in-app preview (play from `SAMPLESTART` for `SAMPLELENGTH`, with Stop), imported lazily inside a small player seam so the page still opens without it and listed as an optional requirement like matplotlib; if pygame-ce's offset playback does not verify on Windows, the fallback is the external player, which plays the whole song. The external-player fallback is restricted to audio extensions and uses `os.startfile`, which is Windows-only. The alternatives, and why they are not the recommendation: carrying nothing in the row and re-reading the cache file when the page opens avoids widening the snapshot, but it needs the cache file present at open time and re-parses on every open for data the parse already held; Pillow from the start buys JPEG and scaling a step earlier at the cost of a dependency the banner does not need; the external player as the only playback is the Python-only option and the simplest code, but it does not play the preview window, which is the feature; deferring playback entirely ships the page sooner but leaves Ian's sketched "play the preview from there" undone; resolving folders by guessing `<root>/Songs` then `<root>/AdditionalSongs` was the first draft's design and is wrong — it finds nothing for a library that lives entirely in an additional folder, which is the owner's own install.

Staging, in order: (1) parse the seven media tags into hidden row keys; (2) roots plus resolution plus Open song folder; (3) the page with images; (4) playback. Each stage is independently green; stage 3 is the visible unit, stage 4 is where the pygame-ce decision lands. Stage 2 ships the Tk-free helpers plus a unit-tested open-folder function — the folder button itself arrives in stage 3 — so stages 1–2 are invisible on their own. Q7 (derive every time) is settled at acceptance, before the stage-2 PR.

## 4. Recommended Design in Detail

The boundary is explicit. `library_sources.py` owns parsing the media tags into hidden row keys; a new Tk-free module `library_media.py` owns resolving media files and grouping the song's rows — `song_roots(cache_dir)`, `resolve_media_file(song_dir, filename, roots, kind)`, `charts_for_song(library_rows, course_path)`, which returns the song's charts ordered by type then difficulty (reusing the grouping at `library_course.py:75`), and `build_song_media(song_dir, roots, rows)`, which resolves the seven tags' files and assembles the media record — all Tk-free, all tested without a window. `song_page.py` owns display only: it is given the song and its already-resolved media and it calls back for everything else. The shell wires it: it derives the roots, builds the media record through `build_song_media`, and hands the page the record. The page must not reach into the filter, the loader, the snapshot store, or the settings; it must not import pygame-ce at module top (lazy import inside the player seam, so a missing pygame-ce degrades the Play button instead of breaking the page).

Constructor contract for the song page — geometry in, callbacks out, on the `data_paths_dialog.py` pattern. The page is built once at startup, like `AdvancedSearch`, `CourseBuilder` and `DataPathsDialog`, and re-raised by `show(song, media)`; that gives one owner for "one preview at a time" and keeps the window's position within a session.

1. `parent` — the window the page opens from.
2. `on_play(path, start, length) -> bool` — starts the preview from the sample start; returns False when it could not start (no audio device, `mixer.init()` failing). The callback itself is `None` when there is no player, which is how the page knows to disable Play; the shell decides that with `importlib.util.find_spec("pygame")`, which answers without importing anything, so the lazy design holds. The player seam normalizes the window before calling `play()`: a length of 0 or less becomes 12 s, the engine's default [CODE: `Song.cpp:72`, `:888–889`]; a start of -1, or a window running past the music length, becomes start 0 for 12 s or to the end of the song, whichever is shorter — the engine recomputes the start from its timing data in the same cases [CODE: `Song.cpp:866–881`], which the viewer does not hold, so the page takes the simple fallback rather than passing a bad window to `play()`.
3. `on_stop()` — stops the preview. The page calls it when the sample length elapses (it owns that timer through Tk's `after`, since `play()` takes no length argument) and when the page closes, so closing the page always stops playback. `show()` on another song, Stop, and a new Play each cancel any pending timer first, so a stale timer can never cut the next preview short.
4. `on_open_folder(path)` — opens the song's folder. The folder is the highest-priority root where `<root>/<song_dir>` is a directory, carried in the media record; the button is disabled when no root holds the folder, and off Windows, since `os.startfile` is Windows-only.
5. `dpi_scale` — the display scale factor, as every dialog takes it.
6. `button_factory` — makes a themed button (`LibraryApp._button`), as every dialog takes it.

`show(song, media)` takes the song — title, artist, pack, and the song's charts, every row sharing its `"Course path"` from `library_rows()`, not the visible rows, so a filtered table still shows every chart — and the media record, a small dataclass (or `TypedDict`) `SongMedia`: banner, background, jacket and CD-title image paths (or `None` where no root holds the file), the music path (or `None`), the music length, the sample window (`SAMPLESTART`, `SAMPLELENGTH`), and the folder (the highest-priority root where `<root>/<song_dir>` is a directory, or `None`). The length and sample window describe the song's music file, so when the opened chart carries its own `#MUSIC` the record carries that file with no length and no sample window. The seven hidden row keys are `Music`, `Banner`, `Background`, `Jacket`, `CDTitle`, `SampleStart`, `SampleLength`; `Music` is the chart's effective value (chart override if present, else the song-level tag). The shell builds the record with `build_song_media` before calling `show`; the page never resolves a path itself. The shell closes the page on a library reload and on a score sync, so a stale page never shows old scores, and the page's window joins `LibraryApp._dialog_is_open()` (`library_visualizer.py:499–505`), so Escape in the main window while the page is open does not clear the search.

The legibility test, the project's standing guideline: a song page shows one song's media and charts and plays its preview; it is given the song's rows and its resolved media paths and calls back for play, stop, and open-folder. A reader can hold that sentence and then read the file.

What the page shows, top to bottom: the banner across the top (PNG via `PhotoImage`, integer subsample to fit; placeholder where the banner is missing or not PNG — and a `TclError` loading a corrupt image takes the placeholder path too); title, artist and pack; background and jacket and CD title alongside; the music file with its length and sample window; the song's charts — all difficulties with meter, BPM and scores. Buttons: Play preview, Stop, Open song folder. Play is disabled when there is no music file or no player; the folder button is disabled when the folder is gone. The page opens at a default size from a new `SONG_PAGE_MIN_SIZE` and `SONG_PAGE_GEOMETRY` in `theme.py` (the theme pairs a geometry with each minimum size) and does not persist its geometry in v1. There is no new settings key in v1: the roots are derived on every page open and there is nothing to seed, edit, or detect. Double-click and Enter on the focused row both open the page, through one callback, `on_open_row`: the binding handles only `identify_region == "cell"`, opens the focused row rather than `selection()[0]`, and leaves headings, empty space below the rows, and multi-selections alone. Single click, selection, column drag, sort and Ctrl+A are untouched.

## 5. What Does Not Change

No new settings key in v1 (roots are derived; `game_install_dir` deferred, §4). Snapshot schema bumps 4 → 5 in stage 1; old snapshots rebuild on the existing one-click prompt (§2). No `HEADERS` change — the media fields are hidden row keys, never columns. No existing row field changes value. No change to table sorting, filtering, the distribution panel, the course builder, or the search language. `requirements.txt` is unchanged through stage 3; pygame-ce enters it only at stage 4, and only if Q2 goes that way. The snapshot file format is unchanged apart from the version number. Media inside Packages zips is out of scope for v1 (§3). Double-click and Enter on a chart row are the only new input bindings.

## 6. Test Plan (for the implementation PRs)

Pins before moves, following the 0010 pattern: parse tests first, in `tests/test_library_sources.py`, with fixture cache text carrying all seven media tags (and a cache with no media tags), asserting the row keys land and that a tag-less cache yields empty keys — plus a fixture with a chart-level `#MUSIC` override asserting the row's `Music` is the chart's file, and a fixture asserting none of the other six tags has a chart-level override. The parse also reports the BANNER/BACKGROUND/JACKET extension counts across the real cache, so the Pillow call is made with data. Roots tests against a synthetic `Preferences.ini` (comma-split entries, deprecated wins when nonempty else Writable for both the song pair and the `AdditionalFolders` pair, later entries in one list outrank earlier ones) and a synthetic cache dir (user-data `Songs` found from it) — plus a missing `Preferences.ini` (roots are just the user-data `Songs`), a non-UTF-8 `Preferences.ini` and a BOM-prefixed one (no crash, additional folders ignored), and a song under no root (the page shows 'not in the known song folders' with the folder button disabled). Resolution tests for a file present in one root, a file present in two roots with the later mount winning, a split pack (banner from one root, music from another), and a missing folder (`None`) for a pack rotated out — plus one test per path form (bare filename, subdirectory, `../`, absolute, drive-letter, VFS-top-relative, escaping `../`), a non-string media value in a hand-edited snapshot, and an extension outside the kind's allowlist. A snapshot round-trip test asserting the new keys survive write/read and that a schema-4 snapshot rebuilds under schema 5. A live Tk test under Xvfb, on the distribution-UI precedent, that a double-click on a chart row invokes the callback with that row's song — and that a single click does not — plus Enter on a focused row, a double-click on a heading, on empty space below the rows, and with a multi-selection. An image test loading a small fixture PNG from `tests/fixtures/` through `PhotoImage` and asserting the page shows it, plus a JPEG fixture asserting the placeholder path and a corrupt-PNG fixture asserting the `TclError` placeholder path. Playback tests against a mocked player, asserting Play passes the sample start and length and Stop is called — no real audio in the suite — plus the sample-window normalization (a blank, zero, or negative length plays 12 s; a start of -1 or an overrunning window starts at 0), the timer lifecycle (Play then `show` on another song cancels the old timer; Play, Stop, Play again runs the full window), and a chart with its own `#MUSIC` (the page shows that file with no length and no sample window).

## 7. Open Questions for Reviewers

- **Q1. Images — dependency-free PNG first, Pillow later?** Recommendation: yes. The banner is PNG in the real cache and `PhotoImage` reads it with no dependency; Pillow buys JPEG backgrounds and smooth scaling as a later enhancement, not a v1 dependency. Stage 1 reports the image-extension counts across the real cache, so the Pillow call is made with data (at a glance [OBSERVED], no song banner is JPEG, though a few pack banners are). The cost is a placeholder for JPEG backgrounds in v1.
- **Q2. Audio — pygame-ce in-app preview, external player, or defer?** Recommendation: pygame-ce, staged last, with the external player as the fallback if offset playback does not verify on Windows. Pygame-ce is the only option that plays the sample window in-app (pygame itself has no Python 3.14 Windows wheel); the external player plays the whole song and is restricted to audio extensions; deferring leaves the sketched playback undone. The page owns the stop timer and calls `on_stop` when the page closes, so playback cannot outlive the window.
- **Q3. Media carriage — hidden row keys, or re-read the cache file at open?** Recommendation: hidden row keys at parse time, on the "Score description" precedent, with a schema bump to 5 in stage 1 so old snapshots rebuild instead of showing "no media" for every song (§2). The seven keys are `Music`, `Banner`, `Background`, `Jacket`, `CDTitle`, `SampleStart`, `SampleLength`; `Music` is the chart's effective value. The page works from snapshot-restored rows. Re-reading avoids widening the snapshot but re-parses on every open and fails when the cache file is gone.
- **Q4. Entry — double-click only, or also a menu or keyboard route?** Recommendation: double-click and Enter on the focused row for v1, through one callback via the new `on_open_row` table input (payload: the focused row). Enter is the paired "open" gesture on Windows and costs one binding; a menu entry is out of v1. The binding handles only `identify_region == "cell"` and opens the focused row rather than `selection()[0]`.
- **Q5. Geometry — persist the song page's size and position, or fixed default in v1?** Recommendation: fixed default, no geometry settings key (there is no new settings key in this proposal at all, Q7). Add `SONG_PAGE_GEOMETRY` alongside `SONG_PAGE_MIN_SIZE`, matching the theme's pairs; the course builder and Advanced Search persist theirs, and the song page can follow in a later step if the window earns it.
- **Q6. Review — Grok sole reviewer, or the full four-model panel?** Recommendation: the full four-model panel ran on this proposal (PR #185), and that was the right call — the factual errors the panel found were engine-fidelity, not Tk. For the stages: Grok alone is not enough for stages 1–2, which need a reviewer who reads the ITGmania source; stage 3 is Tk work where the owner's Windows checks matter more than extra models; stage 4 (new dependency, audio) deserves a second reviewer.
- **Q7. Roots — persist `song_roots` as a setting, or derive the roots on every launch?** Recommendation: derive every time, from `Preferences.ini` and the cache dir when the page opens (about 0.6 ms measured — no load cost at startup or library load, and the list can never go stale). The install `Songs` root cannot be derived, so in v1 it is not supplied and install-folder libraries resolve to "not found"; persisting at most an optional `game_install_dir` is deferred, with no dialog change now. There is no songs-location setting anywhere in the viewer today, so `song_roots` would have been the first list-valued path setting; the course:11.3 precedent is the notes repo's `make_course_gui.py`, not a viewer component.
